# ADR-003: مسار SEO هو Vite Prerender وليس Next.js

**الحالة:** مقبول — يحلّ محل [ADR-002](002-nextjs-storefront-migration.md)  
**التاريخ:** 2026-06-11

## السياق

ADR-002 (2026-05-23) قرّر هجرة المتجر إلى Next.js 15 (`freezone-storefront/`) لمعالجة
ضعف SEO. بعد أسبوعين، تدقيق سباق الإطلاق العالمي (`GAP_REPORT.md` · 2026-06-10) وثّق
الواقع:

- `freezone-storefront/` بقي **هيكلاً مهجوراً من 3 ملفات** — غير منشور ولا يخدم أي زائر.
- لا خادم يولّد HTML في الإنتاج أصلاً: Netlify يقدّم Vite SPA ثابتة.
- سكربت `freezone-web/scripts/prerender.mjs` (خطوة postbuild) نضج فعلياً: قشور HTML
  ثنائية اللغة بعنوان/ميتا/canonical/hreflang/OG/Twitter + JSON-LD لكل منتج
  (≤500 × en/ar) وللصفحات الثابتة، وامتد في سباق 2026-06-10 إلى صفحات الفئات
  والعلامات التجارية، ويفشل النشر بصوت عالٍ عند كتالوج فارغ.
- التوصيل عبر `freezone-web/public/_redirects` (بروكسي sitemap + uploads،
  SPA fallback) و`_headers` (رؤوس أمان، noindex للوحة الإدارة، كاش immutable) —
  ملف `netlify.toml` الجذري **إعداد ميت** يتجاهله مسار النشر الفعلي
  (`nwtgck/actions-netlify`).

أي أنّ أهداف ADR-002 (ميتا لكل صفحة، sitemap يعمل، Schema.org Product/Breadcrumb)
تحققت عملياً عبر الـ prerender دون مشروع front-end ثانٍ. التفاصيل التشغيلية الكاملة
في `SEO_NOTES.md`.

## القرار

1. **مسار SEO الرسمي = Vite SPA + prerender وقت البناء + `_redirects`/`_headers`
   على Netlify.** لا SSR ولا ISR.
2. **التخلي نهائياً عن `freezone-storefront/` (Next.js).** الهيكل يبقى في التاريخ؛
   لا يُستثمر فيه ولا يُنشر (حذفه من الشجرة قرار منفصل لاحق).
3. **ADR-002 ملغى.**
4. أي تحسين SEO مستقبلي يتم بتوسيع `prerender.mjs` و`Seo.tsx` وملفات `public/` —
   لا بإدخال خادم HTML جديد منتصف الطريق.

## البدائل المرفوضة

- إكمال هجرة Next.js (خطة Strangler Fig من ADR-002): مشروعان أماميان وبنية نشر
  ثانية مقابل فائدة وحيدة هي ميتا «حيّة» بدل مجمّدة لكل نشرة.
- خادم Express يقدّم HTML من نفس الـ API: لا يمر عبر مسار النشر الحقيقي
  (Netlify static) فسيبقى غير مُختبَر في الإنتاج.

## العواقب

- مشروع أمامي واحد، مسار نشر واحد مجرَّب، صفر تكلفة تشغيل إضافية.
- **الميتا مجمّدة لكل نشرة (deploy-frozen):** المنتجات/الفئات الجديدة أو المعدّلة
  تحصل على قشرة فارغة حتى إعادة البناء التالية (مكوّن `<Seo>` وقت التشغيل يصحّحها
  للزوار المنفّذين JS وGooglebot في الموجة الثانية). التخفيف: إعادة نشر بعد
  الاستيرادات الكبيرة أو جدولة rebuild دوري.
- **لا HTTP 404 حقيقي** للمسارات المجهولة: الـ SPA catch-all يعيد 200 دائماً؛
  404 فعلي يتطلب Netlify Edge Function مع manifest وقت البناء
  (موثّق في `SEO_NOTES.md` §4) — مقبول حالياً (Google يعاملها soft-404).
- المنتجات بعد سقف `PRERENDER_MAX_PRODUCTS` (500/لغة) بلا قشرة
  (الـ sitemap يغطيها والميتا وقت التشغيل تعمل).
