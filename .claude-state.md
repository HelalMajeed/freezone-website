## Operating rules

- Direct push to `main` for small/safe fixes only.
- Larger work goes on a `claude/<sprint-or-topic>` branch + PR.
- Long-running work (>30min wall time) belongs in GitHub Actions or Fly Machine
  workers, not the local session.
- Never wait for owner approval. Instead, open a GitHub issue:
  - `workaround` + `needs-review` — non-ideal solution applied.
  - `assumption` + `needs-review` — decision made without explicit approval.
  - `blocker` + `urgent` — true hard stop (missing credentials, etc.).
  - `sprint-report` — at end of each sprint.
  - `daily-summary` — auto-posted by the daily workflow.
- Red lines: no destructive DB ops (`reset`, `--force-reset`, `TRUNCATE`,
  `DELETE FROM` on prod tables), no secrets in code/logs/PRs, no Shopify CDN
  or `globaliraq.iq` URLs as final image URLs, no slugs with timestamps, no
  half-finished `✅` reports, no force-push to `main`.
